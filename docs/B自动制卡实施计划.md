# B：自动制卡实施计划

任务依据：`background` 对话中的三人分工及本轮确认。本文是实施计划，未表示下列能力已实现。

2026-10-14 实施进度：M1 的文字制卡闭环已实现。M2 已接入主动开启的原页视觉校准：两次读取、关键内容保护、修改区域局部复识别，符合政策的修正自动保存为机器核对版本，并继续制卡；其余显示差异待确认。M3 已接入本机候选和主动选择视觉检查后的保守附图。已建立十个政策案例和十二张自编印刷测试图的本机 OCR 基线，见 [样本与首轮验证](OCR校准样本与首轮验证.md)；真实云端校准效果与真实讲义人工标注对比尚待验收。使用入口见 [自动制卡使用说明](自动制卡使用说明.md)，交接约束见 [接口与验收](自动制卡接口与验收.md)。

## 目标与交付边界

B 负责把讲义连续处理成有来源依据、附带质量检查结果的图文卡片草稿，减少手选内容、手工修正和逐项操作。

目标流程：导入讲义 → 自动识别与校准 → 提取知识点 → 分批生成卡片 → 匹配图片 → 质量检查与有限修正 → 用户处理疑点并确认。

| 环节 | B 的交付 |
| --- | --- |
| 识别与校准 | 保留原始文字和原页位置；自动生成有依据的修正，定位无法确定的内容 |
| 知识点与制卡 | 自动选择内容，提取知识点、适用条件和证据，生成问题、答案、评分点和引用 |
| 配图 | 自动检索讲义图块，检查相关性、完整性与显示侧；可靠候选附到草稿，其余说明原因 |
| 质量检查 | 发现引用无效、答案依据不足、条件缺失、歧义、重复和图片问题，输出结构化疑点 |
| 运行与评估 | 分批进度、失败恢复、去重、版本失效处理；固定样本上的前后对比 |

A 负责页面、桌面入口和疑点展示；C 统筹 API、存储、卡片版本及 Anki 接入。B 提供可独立验证的处理模块、结果协议、样例和必要的接入适配。共用 `app.py`、`schemas.py`、`db.py` 的变化先在协议说明中列明。

最终批准仍由用户确认。机器检查结果与人工批准分别记录；来源是否可用于制卡也有独立政策，不能用模型自评分冒充人工校对。

## 当前基础与缺口

- 已有本机 PDF 提取、OCR、不可覆盖的来源版本和逐字引用校验。
- `/api/card-drafts` 只处理手选片段：同一材料、最多 6 块、16000 字，每次 1～6 张；前端固定请求 3 张。
- OCR 当前只取识别文字，未保留行框和逐行分数，没有自动校准。
- 现有校验可以发现不存在的引用，不能发现“引用真实但答案错误”。
- 已有本地图块推荐、保守扩图和可选视觉检查；仍需逐卡触发与人工采纳。
- 没有串联知识点提取、生成、审核、修正和配图的整份材料任务。

## 实施顺序

### M0：样本、基线与接口约定

1. 用自编或获准的小样本建立基线，首轮选择约 10～15 页，覆盖文字 PDF、扫描页、表格、公式、多栏和含图页面。卡片数量由实际知识点决定。
2. 人工标注原文、知识点、必要条件、可用引用与配图，并区分调试集和保留验收集。
3. 记录现有流程的人工操作、生成结果、疑点和修改时间。
4. 写出 B 输出协议及来源状态政策，明确 A 的展示字段和 C 的存储、版本、任务接入需求。

交付：固定样本、基线记录、输入/输出 JSON 示例、接口与验收说明。实施代码使用独立 B 任务分支，按里程碑提交可单独验证的变化。

### M1：先跑通文字自动制卡与质检闭环

1. 首先使用粘贴文本和已经确认的 PDF 来源，复用现有生成能力。
2. 按章节、段落和原文顺序组织材料，保留必要上下文；跨块知识点不能因分块丢掉条件。
3. 提取独立知识点及证据，按知识点确定题量；不为了固定题量编造内容。
4. 顺序分批生成问题、答案、评分点和引用，检查知识点覆盖及重复。
5. 先做结构、逐字引用、版本和明确重复的规则检查，再单独核对答案/评分点的原文支持、条件和题目清晰度。
6. 对可修复问题最多尝试一次修正并重新检查；仍不确定的保存为待处理结果，保留原因与来源。
7. 后台任务保存批次、进度和成功结果；失败只恢复失败或未完成部分。同输入重试不重复写卡，处理期间保持模型配置一致。

交付：无需手选片段的文字制卡任务、结构化质检结果、可恢复批次、可交给现有工作台确认的草稿。

本阶段验证核心生成链路；后续 M2 才把未人工逐页确认的 OCR 材料接入，不能把 M1 宣称为完整 PDF 自动化。

### M2：OCR 自动校准与疑点定位

1. 保存逐行文字、框、识别分数、文本位置和原页摘要；分数用于筛查，不能当作正确概率。
2. 检测低分、乱码、阅读顺序、数字、公式、单位、下标和否定词风险。
3. 通过原页局部复识别与受限文本修正产生候选，保存修改前后差异、原因和证据。不能用常识补写讲义没有的结论。
4. 首期只开放在保留样本上验证过、有原图支持的低风险自动修正；关键内容变化和识别分歧进入人工确认。
5. 与 C 约定机器验证和人工校对的不同状态、政策版本及来源资格。通过政策的来源继续自动制卡；待确认页与相关知识点明确挂起，其他可用页面继续处理。
6. 每次改变可引用文字都建立新来源版本和块 ID，保留原识别；相关卡片和检查结果按版本失效。自动修订显式清除旧人工确认标记。

交付：自动校准、原页定位、修正差异、待确认清单，以及只需处理疑点的 PDF 制卡入口。

### M3：自动配图与图文检查

1. 复用现有 Docling 图块解析、引用页候选、扩图和缓存，不另起一套配图引擎。
2. 保存文字草稿后自动准备配图候选。首期每卡至多自动附 1 图，默认答案侧。
3. 检查实际采用的裁图和原页；要求关联得到支持、完整、清晰、无关键裁剪疑点且候选选择明确，才自动附入草稿。
4. 没有独立合适图片时允许文字卡继续；整页备选、多个候选、检查失败或不确定均输出原因，不强行配图。
5. 看图作答必须把必要数值、关系和评分依据写入卡片；题目侧另查答案泄露。
6. 来源、卡片内容、裁剪范围或显示侧变化后，旧检查不能沿用。

交付：自动附图或明确说明无法附图的卡片、可追溯图片来源与质量疑点。

### M4：整合验收与效果对比

1. 接入 A 的进度、疑点列表和原文跳转，接入 C 的任务持久化、版本及批准流程。
2. 用固定样本运行完整链路：导入 → 校准 → 知识点 → 制卡 → 配图 → 质检 → 处理疑点 → 批准。复用已有后续导出能力验证产物兼容。
3. 同一验收材料上比较现有版本和新版本，记录模型、提示、政策、输入版本及重复运行结果。
4. 分开报告程序正确性与真实模型效果，不用离线 mock 测试通过率代替制卡准确率。

交付：可运行链路、固定样本结果、前后对比、演示步骤与可供竞赛报告使用的失败案例。

## 输出协议草案

字段是交接建议，实施前由 A/B/C 共同对齐。

- 任务：`job_id`、材料/来源版本、阶段、批次进度、生成数量、待处理数量、失败原因、可恢复位置。
- 知识点：编号、内容、适用条件、原文片段及逐字证据、覆盖状态。
- 卡片：现有问题、答案、概念、评分点、引用；增加知识点关联和质检结果关联。
- 疑点：目标编号、环节、类型、严重程度、原因、来源页/块/版本、证据、建议动作、检测方式、处理状态。
- 修正：原值、候选值、原因、依据、自动采用或待确认、父版本；保留修改历史。
- 配图：候选/媒体编号、原页、来源版本、最终裁剪框、显示侧、检查结果及自动采纳原因。
- 追溯：模型、提示词/规则/政策版本及输入摘要；不在结果中记录密钥。

建议把处理逻辑分别放入知识点提取、制卡编排、卡片质检、OCR 校准模块，复用现有来源、模型和图片服务；避免集中重写共用入口文件。

## 验收标准

程序验收：

- 一次启动能自动执行各阶段，显示成功、待确认、失败和跳过的具体原因。
- 虚构引用、非法模型返回、过期来源及过期检查不能成为有效结果。
- 批次失败、重试、重复点击、服务中断不会重复写入已完成卡片；已完成产物保留。
- 原文和卡片修改可追溯，旧引用、图片和历史作答不被覆盖。
- 模型或配图能力不可用时结果明确，不把未检查标成检查通过。
- 用户确认后的产物可进入现有练习、导出和同步流程。

效果评估：

- OCR 字符错误率，另列数字、公式、单位和否定词错误；自动修正正确率与覆盖率。
- 卡片无需内容修改即可批准的比例、答案与评分点的依据正确率、知识点覆盖、重复比例。
- 疑点检出率、误报及漏检，尤其统计真实引用但错误答案、条件缺失的案例。
- 自动配图采用比例、人工判定的相关/完整比例、错误配图和题目侧泄题。
- 单份材料人工操作次数、修改时间、模型调用次数、总耗时与失败恢复情况。

在基线取得后确定提升目标。首轮保留样本要求不出现虚构来源、关键内容静默误改或失败被当作通过；结果同时报告样本量和局限，不能宣称对任意讲义保证正确。

第一项实际开发任务：M0 的协议与基线，加 M1 的“知识点提取 → 分批生成 → 质量疑点 → 有限修正”闭环。之后依次接入 OCR 校准、配图及 A/C 的整合。
