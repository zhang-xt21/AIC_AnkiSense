# OCR 校准样本与首轮验证

> 历史记录：保留当时的方案与验证范围，不代表当前版本的完整行为。当前入口见[文档导航](../README.md)。

记录日期：2026-10-14。全部材料为自编数据；没有使用个人讲义，也没有请求真实云端模型。

## 可复现入口

```powershell
.\.venv\Scripts\python.exe tools/evaluation/evaluate_source_calibration.py --output .local/ocr-eval --local-ocr
```

脚本不加载 `.env` 或个人模型设置。它在输出目录生成测试图、隔离模型缓存及 `report.json`。本机模型来自锁定的 RapidOCR 依赖内置权重，不需额外云端调用。

## 两类结果分别解释

十个政策案例使用预设视觉读取响应，覆盖未修改、局部支持的字形修正、数字改变、否定改变、公式、两次读取不一致、局部复识别不一致、图像不确定、缺少位置和大范围重写。十项预期均符合。它们验证“该采用还是等待确认”的程序边界，不能当作真实模型的识别或纠错准确率。

另有十二张自编印刷测试图，使用真实本地 OCR 推理，覆盖清晰中文、数字条件、降质图、段落、小字、单位、否定条件、公式、英文、双栏、表格和旋转页。

比较时忽略空白，保留标点和字符，采用 Levenshtein 编辑距离。合计字符错误率为 31/479，约 6.47%。双栏的标准顺序是先左列后右列；实际识别按交错行序输出，导致大部分差异。筛查结果为该样本给出 `reading_order`，自动采用政策会要求人工确认。

这只是小规模、字体和排版受控的本机基线。其他十一个样本没有差异，不表示能够正确处理任意讲义，也不能据此推断云端校准能修复双栏顺序。

## 已验证的软件行为

- 原页读取两次，其中一次不提供原 OCR 文字；图片只在用户主动启用或点击时发送。
- 数字、中文数词、单位、否定、英文标识和公式符号改变时不自动采用。
- 修正需得到原图局部整行复识别支持；读取分歧、不确定、大范围重写和缺少位置均交给用户。
- 自动采用时保存新来源版本、原始 OCR、差异、政策、模型与原页摘要；页面标记为机器核对，卡片仍为草稿。
- 机器核对来源可继续提取知识点和制卡。人工批准后可导出和同步，包括来自该来源页的图片。
- 相同文字转为人工确认时保留块身份，追加人工确认事件；修改文字时建立新版本并使旧引用失效。
- 并发修改拒绝旧结果覆盖，校准失败不能成为通过；运行期间不能更换模型设置。
