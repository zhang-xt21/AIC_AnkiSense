# 公式JSON与单卡学习目标修复

> 历史记录：保留当时的方案与验证范围，不代表当前版本的完整行为。当前入口见[文档导航](../README.md)。

日期：2026-10-29。基于当前0.1.17源码修改，尚未重新打包。本轮只使用旧案例与离线测试，没有调用真实API，也没有启用新收集的独立评估候选。

## 问题与改动

### 公式数据格式

上轮线性代数请求105、106、108、109均收到HTTP200及完整结束标记，但模型在JSON字符串中直接写了数学定界符的单反斜杠，导致严格JSON解析报Invalid escape，整批卡片无法读取。

新增model_json.load_model_json：先严格解析，合法JSON的值保持原样。只有遇到非法转义时才使用受限解析器；仅允许在question、answer、minimal_answer和rubric文本中，修正数学定界符前缺失的一层JSON转义，并要求该字符串的数学定界符成对匹配。对象结构、引号、逗号、截断、未知数学命令等错误继续拒绝。

evidence、各种citation、exact_quote、answer_spans等原文字段不参与修正；同一返回中若原文字段损坏，仍整份拒绝。这个处理不是通用JSON修复器，不保证能恢复所有模型格式错误，也不会猜补公式或知识。普通合法JSON中的代码、路径、换行与引用值不被改写。

模型提示词补充合法JSON示例，明确区分JSON中的双反斜杠和解码后的展示文字。没有增加内部模型请求或隐藏重试，调用预算计数方式保持不变。

### 卡片学习目标

整卡/原页语义审核结果新增必填learning_scope：列出每个独立目标及其题干连续原文、解释目标关系，并给single/multiple/uncertain结论。服务端校验题干摘录、重复项和目标数量；multiple或uncertain即使模型写pass也不能通过。模型判断多个目标时，自动流程以multiple_concepts进入现有修复分支。

保留同一目标下紧密相关的提问，例如定义及必要条件、判断及理由；不按问号、评分点或公式数量机械拆分。修复接口仍只返回一张卡，保留一个有完整来源的核心目标，其余目标后续另行制卡；本次没有把单卡修复改成自动生成多张，避免突破任务数量预算。

已知的二分查找多阶段堆叠、信念特性与层次关系混问还增加了窄范围本地拦截，覆盖保存后审核、自动制卡一致性检查以及独立最短答案放行门槛。这是对已知问题的补强，不是用正则判断所有语义；其他内容仍依赖结构化语义审核和人工评审。
