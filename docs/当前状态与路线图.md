# 当前状态与路线图

基线日期：2026-09-27。当前是能演示完整链路的本地原型，团队仓库整理不等于所有功能已经产品化。

## 已实现

| 能力 | 当前行为 |
| --- | --- |
| 讲义导入与 OCR | 文字 PDF 提取、RapidOCR 本地印刷文字识别、原页渲染、逐页校对与版本 |
| 图文制卡 | AI 草稿、问题/答案/评分要点/引用编辑、原图与截图、推荐配图、裁剪和正反面预览 |
| 审核与追溯 | 已批准卡片才进入练习和导出；来源更改触发重新审核；历史作答保留快照 |
| 答题诊断 | 正确、遗漏、矛盾、无法判断等反馈；按评分要点提供依据，失败保留作答 |
| 练习交互 | 下一张、完成状态筛选、最近作答与已审核的补充练习匹配 |
| 模型配置 | 页面配置自选兼容 API，也支持本地演示模式 |
| Anki 连接 | APKG 图文导出、自有 v1 接口、同步插件；使用 Anki 原有复习能力 |

当前图片视觉检查是独立操作，回答诊断仍以文字原文和评分要点为依据。AI 生成卡片仍需要人工审核，“练习已完成”只表示获得分析结果，不等于答对或掌握。

## 已验证与未验证

新仓库已经实际执行默认初始化、依赖一致性检查，完成 520 项 Python 测试（13 项跳过）、46 项前端测试和 32 项浏览器检查。浏览器使用本机 Chrome，未重新下载默认 Chromium；跳过项包括符号链接权限、尚未安装的 Anki 与 Docling 环境。详见 [仓库准备验收](仓库准备验收.md)。其他成员仍需在自己的电脑执行适用检查；更早的 [历史记录](../测试记录/README.md) 不与本轮数量累加。

真实讲义、OCR、Docling 候选图、云端生成/诊断，以及官方 Anki 运行时已有小样本证据。边界仍包括：

- 最新 `v3-rubric-boundaries` 提示词已做离线结构和边界测试，尚不能据此宣称真实模型分类准确率。
- 配图测试集中在同一份讲义的少量页面；“前三候选覆盖内容”不等于首选图片准确，也不代表所有课程效果。
- OCR 对复杂公式、上下标、箭头、手写及多栏版面仍可能遗漏，需要人工核对。
- Anki 官方导入引擎和隔离集合、Qt 离屏检查已有记录；完整主窗口操作和更多版本兼容仍需收尾。
- 历史云端生成曾出现格式不完整和调用失败，不能因离线测试通过而称为彻底解决。

## 第一阶段：开始协作

验收目标：每位成员可以从干净源码目录独立启动演示，并完成一次小任务 PR。

1. 完成安装说明、脚本、源码忽略规则和基础自动测试入口。
2. 建立远程仓库、邀请成员，约定 `main` 与 PR 评审流程。
3. 成员在自己的电脑安装，跑通演示和相关离线检查，记录差异与失败。
4. 确认模块负责人，各完成一个小问题的提交与互相评审。

本地脚本或 CI 配置已存在不代表远程服务已经启用，是否成功以实际安装和推送后的运行结果为准。

## 第二阶段：固定一条可重复演示的流程

选用自编或获得使用许可的一小节讲义，固定演示步骤与人工核对项：导入 → 校对 → 出题 → 图文编辑 → 批准 → 多类回答 → 导出/同步 → Anki 复习。

优先修复阻断流程的错误、明显误导的反馈、丢失编辑内容以及图片不完整等问题。保留调用失败原始记录，不用重复重试后的成功覆盖首次失败。

## 第三阶段：证明效果，再决定桌面整合

- 准备人工标注的题目与答案，覆盖换一种说法、答对一部分、明确矛盾、无关/不知道和输入干扰。
- 固定模型、提示词、材料与预算，比较前后版本；单独统计生成可用性、分类结果、配图覆盖、耗时和调用失败。
- 邀请队友试用完整流程，记录审核工作量和窗口切换成本。
- 根据这些证据确定统一桌面客户端的实现方式，再开展 Anki 内部工作台和作答窗口等整合。

## 暂未承诺

全自动可信审核、视觉模型直接评分、图片挖空、多轮追问、账号系统、多人共用学习数据库、公网部署、手机适配以及 Anki 调度算法改造，均不属于当前已完成能力。项目开源许可证、第三方声明与发布材料范围需在公开发布前确认。
