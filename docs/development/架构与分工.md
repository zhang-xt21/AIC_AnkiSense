# 架构与分工

AnkiSense 是独立仓库，集中管理网页、后端、文档处理和自有 Anki 插件。Anki 官方程序独立安装，不在本仓库修改其源代码或复习调度算法。

## 当前链路

```text
PDF / PPT / 文字
   ↓ 本机提取、OCR 与来源版本
AI 提取学习目标 → 生成图文卡片 → 自动检查
                                ├─ 通过 → 练习 / 导出 / 同步 Anki
                                └─ 有疑点 → 修复、重试或人工处理
```

网页和 FastAPI 服务在本机运行，SQLite 保存材料、卡片、作答及历史快照。PDF 引用页在本机渲染，可裁剪并保存来源。云端文字模型提供生成和作答诊断，可选图片检查单独调用支持图片输入的服务。

## 模块边界

| 模块 | 主要位置 | 职责 |
| --- | --- | --- |
| 网页交互 | `ankisense/static/` | 材料、制卡、练习、导出、模型设置；展示后端状态，不自行决定审核与评分结果 |
| API 与数据 | `app.py`、`db.py`、`schemas.py`、`paths.py` | 请求、校验、事务、版本与本机路径；数据库默认在被忽略的 `data/` |
| 来源与 OCR | `ingest.py`、`ocr.py`、`sources.py`、`evidence.py` | 文字/OCR 提取、原页、确认校对、引用和来源有效性 |
| 图片处理 | `media.py`、`figure_*.py` | 保存图片、原页渲染、裁剪与直接视觉检查 |
| AI 与作答 | `llm.py`、`prompts.py`、`model_settings.py`、`attempts.py` | 生成、诊断、模型配置、证据校验、调用失败与回答记录 |
| Anki 接口 | `plugin_api.py`、`plugin_sync.py`、`apkg.py` | v1 本机鉴权接口、导出与同步数据契约；不直接写 Anki 学习库 |
| Anki 插件 | `addons/ankisense_sync/`、`examples/anki_plugin_client.py` | 本机连接、图文卡片同步、Anki 内作答和反馈；不代替 Anki 评分 |
| 验证工具 | `tests/`、`tools/` | 离线回归、浏览器检查、安装构建及额外环境验收 |

表中 Python 文件名均相对于 `ankisense/`。三人并行开发先对照 [协作接口契约](协作接口契约.md)，后端协议详情见 [插件接口 v1](插件接口说明.md)。已安装插件且完成安全同步的卡片，在 Anki 复习时可直接打开作答窗口；PDF 导入和制卡仍在网页完成。

## 建议分工

按人数与经验分配以下职责；它们是责任边界，不是三个各自独立的产品：

- **界面与体验负责人**：制卡工作台、练习导航、图片展示、键盘与窄屏体验，同时维护相关前端与浏览器测试。
- **服务与集成负责人**：API、数据库版本、模型配置、同步与导出，对跨模块契约变更负责。
- **文档与效果负责人**：OCR、图块推荐、人工标注案例、模型诊断质量与验收报告，协同调整算法实现。

每项任务仍指定一个作者和一个评审者。数据库结构、插件协议、审核规则、卡片身份和来源快照属于共同依赖，修改前先把请求/响应或行为示例写进 Issue，再分配两端实现。不要同时让多个任务重写整个 `app.py` 或 `static/app.js`。

## 团队共享与本机状态

仓库共享源码、锁定依赖、自编示例和脱敏测试资料。模型密钥、讲义原件、学生回答、SQLite、Anki 资料和下载模型属于每个人的本机状态，不通过 Git 同步。

本次整理建立了新的源码目录，未复制旧开发目录的学习数据。第一次启动将创建自己的空学习空间。若以后确有迁移个人数据的需求，应先停止对应服务、备份完整数据并单独迁移；不要让两个运行中的服务共同写同一份数据库。

## 桌面形态

当前采用 Electron 桌面窗口，复用网页与本机 FastAPI 后端，提供 Windows 安装包。Anki 是可选的外部复习客户端，通过自有插件配对和同步；不维护 Anki 源码分叉。构建与验收入口见[桌面端说明](../../desktop/README.md)。
