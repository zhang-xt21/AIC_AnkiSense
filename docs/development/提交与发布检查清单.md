# 提交与发布检查清单

用于准备仓库交付，不替代比赛官方要求。最终附件清单仍需逐项核对正式通知。

## 源码与版本

- [ ] 核对本地所有未提交改动，保留各位成员成果，完成整合评审。
- [ ] 在最终提交上重跑相关后端、前端、浏览器、桌面与 Anki 验收。
- [ ] 将通过验收的版本合入 `main`，推送并从远程重新检出验证。
- [ ] 创建提交用版本标签，记录完整提交 SHA；后续开发不覆盖该标签。
- [ ] README、桌面版本、后端版本、安装包及测试说明一致。

## 公开内容

- [x] 项目自有代码采用 AGPL-3.0-only，标准条款见 [LICENSE](../../LICENSE)。
- [ ] 完成第三方许可与发行义务核验，保留上游许可和来源声明。
- [ ] 检查拟公开文件及 Git 历史中的密钥、连接凭据、个人数据和无权分发材料；若发现真实密钥泄漏，先撤销密钥。
- [ ] 用自编示例验证全流程，仓库内文档使用相对链接。
- [ ] 补齐 README 和演示指南的截图，移除“截图预留”注释。
- [ ] 效果结论与冻结版本匹配，区分机器审核、人工标注和工程测试。

## 安装包与试用

- [ ] 干净 Windows 环境完成安装、启动、重启和升级检查。
- [ ] 验证模型配置、错误提示、取消与继续任务、导出和删除。
- [ ] 隔离 Anki 中验证配对、首次同步、重复同步、图片、内部作答和进度保留。
- [ ] GitHub Release 附安装包、校验值、更新说明和已知限制；安装包不提交到源码目录。
- [ ] 分发包附 LICENSE、第三方声明及匹配版本的源码获取方式；现有 0.1.19 安装器没有因本次许可配置而重打包，需另外附带这些文件。
- [ ] 从 Release 实际下载附件，确认可安装，再更新 README 的精确版本链接。
