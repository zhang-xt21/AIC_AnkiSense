# 三人联调约定 v0.1

这份约定只列界面、自动制卡、服务与 Anki 集成之间必须对齐的内容，目标是先跑通一份讲义的完整流程。字段以 [`ankisense/schemas.py`](../../ankisense/schemas.py) 为准；Anki 同步的细节见[插件接口说明](插件接口说明.md)。改动交接字段时，同步更新相关测试和本文。

## 先统一四件事

1. **同一张卡片使用稳定 ID。** `document_id`、`block_id` 和 `card.id` 由服务端生成；编辑、审核和再次同步不改变 `card.id`。Anki 用它对应同一张笔记。
2. **AI 输出统一格式并附原文引用。** 制卡结果包含 `question`、`answer`、`concept`、`kind`、`rubric[]` 和 `evidence[]`；每条引用提供 `block_id` 和原文中的逐字 `quote`。生成结果先保存为 `draft`，配图可留空，不能编造图片关联。
3. **区分草稿和已批准卡片。** `status` 使用 `draft`、`approved`、`rejected`。自动流程保留经过验证的 `automatic_evidence`；独立整卡机审记录 `approval.method=machine`，备用人工批准记为 `human`。服务端统一验证这些证明及来源是否仍有效，不能只读 `status`；真实改文使旧批准失效。
4. **重复同步保留 Anki 学习进度。** 同一个 `card.id` 更新原有笔记，不创建重复卡片；本次清单里没有出现的卡片不自动删除。Anki 的复习评分仍由用户选择。

## 这轮怎么对接

| 环节 | 输入与出口 | 本轮完成标准 |
| --- | --- | --- |
| 默认导入 → 自动制卡 | `POST /api/material-imports` 上传 PDF/PPT/PPTX；可选 `count`（1–600）、`auto_images`。读取任务返回的 `plan`、进度和卡牌。 | 自动建议张数，原页独立视觉检查，逐张保存有效卡牌；无效候选不拖垮同批其他卡牌。 |
| 失败或中断 → 补跑 | `POST /api/material-imports/{id}/retry`；任务返回 `retryable`。 | 复用已保存文件，只补跑未完成知识点；服务重启标为 interrupted，不自动发起付费请求。 |
| 讲义 → 数量建议 | 导入后调用 `POST /api/documents/{id}/generation-plan`；默认不传 `block_ids`，使用整份讲义当前可用原文，`count` 可省略。 | 本机返回建议数量、范围与分批说明，不调用模型；用户可改为 1–30 张，手选片段放在高级设置。 |
| 开始制卡 → 草稿 | `POST /api/generation-jobs` 提交 `document_id`、可选 `block_ids`、`count`、规划返回的 `source_fingerprint` 和稳定 `request_id`；`auto_images` 默认为 `true`。 | 立即返回任务；逐批保存 `draft` 并排机审，生成前后检查来源，保留逐字引用；材料不足允许少于目标数量。 |
| 自动配图 | 生成输出 `image_intent: {need: none/helpful/required, reason, block_ids}`，其中片段必须属于本卡引用；旧卡缺省无需图片。进度在 `card.auto_illustration`。 | 辅助配图不阻塞文字检查；必需配图未通过时不能学习。只有检查通过才附图并增加版本，保留现有附件；前端轮询不可覆盖未保存编辑。 |
| 草稿 → 审核 | 界面从 `/api/state` 读取卡片，用 `PUT /api/cards/{id}` 保存正文、引用、评分要点、状态和可选 `images[]`。新界面应传 `expected_version`。 | 用户能检查并批准卡片；收到 409 时保留未保存的编辑并提示重新核对。 |
| 自动机审 | 云端配置齐全时生成、保存草稿自动排队；`POST /api/cards/{id}/auto-review` 携 `expected_version` 用于主动重试；`GET` 只读结论。 | `review_state` 为 queued/running 时轮询，完成后 auto_pass/attention/needs_review；通过自动批准，有疑点仍为草稿。 |
| 已批准 → Anki | 插件使用 `/api/plugin/v1` 的状态和卡片接口；`card.id` 对应 Anki 的 `NoteID`。 | 已批准卡片和配图正常更新，重复同步后复习记录仍在。 |
| Anki → 作答 | 插件提交 `card_id`、`card_version`、`answer`、`request_id`。 | 在 Anki 内看到 AI 反馈，再自行选择复习评分；失败时保留输入。 |

`card.version` 在成功编辑后递增；新界面用它避免覆盖较新的版本。`images[]` 的每项使用 `media_id`、`side`（`question` / `answer`）和 `caption`。当前 AI 作答分析依据题目、答案、评分要点和原文，不理解图片内容。字段限制、媒体校验和 Anki 笔记模板沿用现有服务与[插件接口说明](插件接口说明.md)，这轮不另造一套格式。

`/api/state` 的 `generation_jobs[]` 提供目标数量、已生成数量、批次进度和状态；也可读取 `GET /api/generation-jobs/{id}`。网络中断后先查询任务，再用相同 `request_id` 重试创建，避免重复生成。`POST /api/generation-jobs/{id}/stop` 停止后续批次，当前批次完成后保留结果；服务重启把未完成任务标为 `interrupted`，不自动继续调用模型。旧 `POST /api/card-drafts` 保留给已有调用方，每次仍限 1–6 张，新界面使用后台任务。

后台任务逐张校验候选。`generated_count` 和 `card_ids` 仅包含已保存的有效卡片；`rejected_count` 及 `rejected_cards[]` 记录未通过格式或引文校验的候选。每项含 `batch`、`index`（均从1开始）、`question`、`reason`、`draft_preview` 和 `preview_truncated`；预览是上限12000字符的纯文本JSON，前端应按文本显示。未通过候选不进入学习卡片库、不排机审、不自动重试，其余卡片和后续批次继续处理。实际保存少于目标时为 `partial`，全部候选均无效时为 `failed`。批次本身格式异常、超量返回、网络失败或来源整体变化仍终止任务。旧严格数量接口的行为不变。

未确认但有效的当前非空原文可用于制卡与新版本机审，逐页人工确认是可选操作。机器批准绑定持久化机审记录、卡片内容、来源版本和配图结论；不能只相信 `status`。确认原文但未改文字时保留 `revision` 和 `block_ids`；真实改文或重新 OCR 后生成新版本，关联卡片退回草稿并清除批准。仅机器批准状态变化不增加 `card.version`。

## 原文信号、提纲与评分范围

- `/api/state.source_pages[].quality` 为本机计算的提取疑点，含 `needs_attention`、`issues[{code,message}]`、OCR 行数及低置信度行数；不代表准确率。新 OCR 保存 `ocr_lines[{text,confidence?,bbox_pixels?}]`，坐标相对于渲染 PNG。旧页不要求补跑 OCR。
- 制卡计划新增 `topics[]`（`id/title/page/block_id/start/end/kind`）和 `source_signals[]`；张数结合标题、编号、条目及字数估计。原 `stats.coverage_ratio` 仍仅表示原文字符范围覆盖。
- 任务 GET 和 state 新增 `coverage`：`method/stale/topics/matched_count/total/note`。候选的 `status` 为 `possible_match/unmatched`，`matched_card_ids` 只是题目词面匹配；没有匹配的条目用于查漏，不会自动补题。源版本变化时 `stale=true`，不能沿用覆盖结论。
- 机审格式新增 `minimal_answer/minimal_answer_citations`、`question_coverage/missing_question_parts`，以及逐条 `rubric_checks[].scope/scope_reason`。scope 为 `required/background/uncertain`，仅全部 required、逐字依据有效、题目要求覆盖完整时可 pass。评分范围检查复用整卡机审这次请求，不额外发起专门调用。
- 两种机审证明均校验当前卡片、来源和图片版本。符合原策略的 LIN 自动证明仍可使用；过期或缺失必要字段的记录呈现为 `status=draft, approval_stale=true`，保留历史，不自动重跑付费审核。

## 桌面端联调范围

Electron 桌面壳复用网页和 FastAPI 服务，默认连接本机 `127.0.0.1:8765`。启动通过 `/health` 检查 `application: "AnkiSense"`、`api_version: 1`、`status: "ok"`；同一用户目录只运行一个实例，退出只停止本实例创建的后端，复用服务继续运行。独立后端和 NSIS 安装包构建见 [desktop/README.md](../../desktop/README.md)。默认自动导入是主入口，上表的 `generation-plan/generation-jobs` 保留给高级补充制卡。

## 联合验收

三方用同一份小讲义完成“导入 → 生成草稿 → 核对引用原文、审核与配图 → 同步 Anki → 作答”，再检查重复同步和一次失败重试。界面负责人确认 409 时如何保留编辑；自动制卡负责人确认输出符合 `CardDraft`。还需确认只确认原文不会使草稿过期、真实改文会使旧引用失效。验收结果写在 PR 中。
