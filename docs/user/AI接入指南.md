# AnkiSense AI 接入指南：先接通，再验证

适用版本：当前本地原型。接口资料核对日期：2026-09-24。

**可以直接在侧栏「模型设置」填写模式、API 地址、模型名称和密钥。** 保存后即时生效。默认勾选「保存后用新模型继续当前制卡」时，会停止当前制卡的旧请求并用新配置续跑未完成部分，产生相应 API 用量；没有正在制卡的任务时，仅保存不会调用模型。修改设置无需重启。详细步骤见[制卡工作台使用说明](制卡工作台使用说明.md)。

页面保存的配置位于数据目录的 `model-settings.json`，优先于环境变量和 `.env`。以下手工编辑 `.env` 的方法适用于尚未在页面保存配置的情况；已保存后请统一使用「模型设置」，避免改错配置来源。

本指南以项目已有的 DeepSeek 配置示例说明文本生成和答题分析。逐页 AI 校对另外要求所选模型支持图片输入；填好 API 地址和模型名称并不能证明视觉能力。这里只提供配置与验证步骤，没有替你创建账号、充值或调用付费模型。

日常页面操作先看[使用教程](使用教程.md)。

## 1. “接 AI”到底要准备什么

网页已经有调用模型的代码。接入时，你需要准备模型平台账号，并把以下信息填入「模型设置」。也可在尚未保存页面配置时，使用后文的 `.env` 方法。

| 配置 | 可以怎样理解 | 本例填写内容 |
| --- | --- | --- |
| `AI_MODE` | 使用演示规则，还是请求真实模型 | `cloud` |
| `AI_BASE_URL` | 模型服务的接口地址 | `https://api.deepseek.com` |
| `AI_MODEL` | 调用哪个模型 | `deepseek-flash` |
| `AI_API_KEY` | 允许本项目使用你账户额度的密钥 | 你在平台创建的完整 Key |
| `AI_TIMEOUT_SECONDS` | 等待响应的超时设置，单位为秒 | 本指南先用 `90` |

接口地址和模型名来自 [DeepSeek 官方快速开始](https://api-docs.deepseek.com/)。模型名称可能更新；以后出现“模型不存在”时，回到该页核对。

API Key 类似程序调用模型时使用的密码。它只放在本机配置文件中，不用粘贴到聊天里，也不要放进网页截图或公开代码。

## 2. 在官方平台创建 Key

1. 打开 [DeepSeek 开放平台](https://platform.deepseek.com/)，按页面提示注册或登录。
2. 进入 [API Keys 页面](https://platform.deepseek.com/api_keys)，按页面提示创建密钥，可以将用途命名为 `AnkiSense`。
3. 将完整密钥复制到你自己的安全位置，下一步要填入本机文件。密钥不要填写成登录密码。
4. 检查平台可用余额或额度。模型 API 按输入、输出 token 用量计费，价格与可用额度以平台为准；如需充值，由你在官方平台自行完成。先做少量测试，再决定后续预算。[官方计费说明](https://api-docs.deepseek.com/quick_start/pricing/)

平台登录后的按钮名称可能调整，以实际页面为准。能在聊天页面对话，并不能替代创建本项目调用所需的 API Key。

## 3. 打开本机配置文件

在项目根目录（含 `start.ps1` 的文件夹）打开 PowerShell；可在资源管理器进入该文件夹后，在地址栏输入 `powershell` 并回车。以下命令都从这个目录执行。配置文件的位置是：

`.env`

注意：文件名是 `.env`，开头有一个点，没有 `.txt` 后缀。`.env.example` 是样例文件。程序仅在没有页面保存的 `model-settings.json` 时，从环境变量及 `.env` 读取配置。

在该 PowerShell 窗口里复制运行：

```powershell
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
notepad .\.env
```

这段命令在缺少 `.env` 时复制样例；已经有 `.env` 时直接打开原文件，不覆盖已有配置。若当前窗口正在运行网页服务，先在那个窗口按 `Ctrl+C` 停止服务，再输入命令。

记事本打开后，将对应的五项配置改成：

```dotenv
AI_MODE=cloud
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-flash
AI_API_KEY=把这里替换成你自己的完整APIKey
AI_TIMEOUT_SECONDS=90
```

只把第四行等号后面的占位文字换成真正的 Key，其他行按示例填写。如果文件内还有数据目录等自己的设置，保留它们。不要重复添加同名配置项。按 `Ctrl+S` 保存，关闭记事本。

不要把上面五行当成 PowerShell 命令运行；它们是写进 `.env` 文件的文本。

这里的 `AI_BASE_URL` 不要加 `/chat/completions`，程序会自动补上。不要填聊天网站地址。

## 4. 重启 AnkiSense

如果旧服务仍在运行，切换到它所在的 PowerShell 窗口，按 `Ctrl+C`。然后从项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn ankisense.app:app --host 127.0.0.1 --port 8765
```

当窗口显示 `Uvicorn running on http://127.0.0.1:8765`，打开或刷新 [AnkiSense 网页](http://127.0.0.1:8765)。使用期间保持 PowerShell 窗口开启。

右上角应显示“云端模式 · deepseek-flash · 未验证”。进入「模型设置」，保存完整的自配 API 设置后点击「验证连接」。测试只发送一次固定短文本，会消耗少量 API 额度，不发送学习材料；成功后圆点变绿并显示「验证通过」，失败则变红并在设置页说明原因。测试检查文字请求与 JSON 输出，不验证图片能力。绿色代表上次测试成功，不保证持续在线；保存配置或重启服务后需重新验证。接下来可继续验证实际作答与生成效果。

## 5. 用一次新作答验证真实连接

先验证答案分析，成功后再尝试生成题目，方便定位问题。

1. 在“讲义制卡 → 导入讲义”里导入自编演示材料。已经导入过的，不需要重复导入。
2. 在“讲义制卡 → 机审与批准”里找到“栈的出入顺序规则是什么？”，确认题目与原文后点击“核对并批准”。
3. 进入“开始练习”，选择这道题。
4. 输入 `最新放进去的元素会先被取出来`，点击“提交回答并分析”。这是一次新的提交，不要仅打开以前的演示记录。
5. 应获得本次分析结果和原文依据，且本次结果不应带“演示反馈：由本地规则生成”的标记。若只有“分析失败”，说明还没有完成一次可用的分析。
6. 到模型平台查看使用记录或用量变化；平台统计可能存在延迟，可作为调用来源的补充核对。

这个答案的教学预期是“正确”，因为它表达了后进先出。若返回其他结论，要检查模型反馈与评分要点，记录为需要复核的案例；“接口能调用”和“判断可靠”是两个不同的验收项。

切换模式后，旧记录仍保留当时的演示标记，这是正常的。新配置只影响之后发起的分析。

## 6. 验证生成卡片

1. 返回“讲义制卡 → 导入讲义”，选择自编“栈与队列”材料。
2. 在原文区勾选栈、队列、空结构这三个片段。
3. 点击“生成 3 张卡片草稿”。先只点一次，等待返回。
4. 页面会进入“制作卡片”，确认新增了三张待审核卡片；保存修改后进入“机审与批准”。
5. 逐张核对问题是否清楚、答案是否正确、引用是否支持结论，再批准使用。

新生成的题目不保证每次相同。系统检查字段、编号和逐字引用，内容仍需人工核对。若返回“格式或原文引用未通过校验”，表示本次结果没有作为可用草稿入库，需要检查或重试。

上述两种调用都成功后，再导入真实课程讲义。生成时只有选中的片段发送给模型；诊断时发送题目、审核后的参考答案与评分要点、关联原文和学生回答。完整 PDF 在本机解析，不会整份上传给模型；主动使用逐页 AI 视觉校对时，会发送所选页的 PNG 原图和该页当前已保存文字。原文、答案或原页图像中的个人信息不会被自动去除。

### 按需验证逐页 AI 视觉校对

先选一页可公开用于测试、含有明确文字的 PDF。进入「讲义制卡 → 导入讲义」，展开「检查原文」后点击 **「AI 校对当前页」**。首次请求会向当前配置的模型发送该页图片，可能消耗 API 额度；同一版本和请求策略的结果可复用。收到建议后，比较页面上的「当前已保存原文」「AI 建议文字」和疑点，再对照 PDF 原页；点击「将建议填入编辑框」也不会直接保存，仍须人工点击「保存并确认校对」。此项校对可按需使用，生成草稿不会自动触发。

需要处理多页时，可点击 **「AI 校对未确认的 N 页」**。界面会先确认发送范围，再逐页请求，失败页不自动重试；可停止后续页面。模型错误、超时或返回无效 JSON 时，本机原文和编辑草稿保持不变。若接口拒绝图片，请检查所选模型是否支持视觉输入；即使接口返回成功，也要核对它是否真的读到了图像，不要只凭一次成功响应判断准确率。演示模式不能使用这项云端功能，本地 OCR 和手工校对仍可用。

## 7. 常见问题

| 看到的情况 | 先检查什么 |
| --- | --- |
| 右上角仍是“演示模式” | 是否编辑的是 `.env` 而非 `.env.example` 或 `.env.txt`；是否写了 `AI_MODE=cloud`；是否停止并重启旧服务、刷新网页 |
| 显示“云端模式 · 待配置 API Key” | `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY` 是否都有值 |
| 显示“模型服务拒绝访问” | Key 是否复制完整、仍有效，账户是否有相应模型权限 |
| 显示“额度不足或请求过于频繁” | 官方平台的可用余额和限流提示；稍后再试，不要连续点击 |
| 显示“暂时不可用”或“无法连接” | 地址是否为官方 API 地址、模型名是否正确、网络是否可达；如仍失败，把页面错误文字发来，不附密钥 |
| 显示“模型调用超时” | 稍后重试；必要时把超时设置提高至 `180` 后重启。等待更久不保证成功，先用短输入排查 |
| 显示“未返回完整的 JSON”或“引用未通过校验” | 模型可能返回空内容、截断内容或不合要求的结果。减少所选原文、重试一次；持续失败需要检查模型参数或提示配置，不能仅增加等待时间 |
| AI 校对按钮不可用或模型拒绝图片 | 在「模型设置」确认云端模式、地址、模型和密钥均已配置；再核对所选模型是否支持图片输入和 JSON 输出。仍可使用本地 OCR 与手工校对 |
| 页面出现以前的“演示反馈” | 查看的是历史记录；新提交一次答案进行验证 |
| 修改 `.env` 后配置还是旧值 | 本项目优先读取已有进程环境变量。可新开 PowerShell 再启动；若设置过系统级同名变量，仍需检查对应变量。不要为了排错把完整密钥打印出来 |
| PowerShell 出现 `WinError 10048` | 端口已经被某个程序使用。先试打开当前网页；要应用新配置，应停止原先的 AnkiSense 服务后再启动，不要随意结束其他程序 |

卡片生成和答题分析的单次输出上限在代码中设为 4096 token；逐页视觉校对使用 8192 token 上限。当前官方 DeepSeek 的 `deepseek-flash`、`deepseek-v4-pro` 请求显式设置 `thinking: {"type": "disabled"}`，覆盖制卡、答题分析、整卡机审、逐页校对和配图检查；其他服务不会收到这个专用字段。切换后的新校对和整卡机审不会复用旧思考配置的缓存，历史结果仍保留。长页面和输出量仍会影响等待时间，具体速度和质量需用真实材料对比；持续截断时应缩小选择范围，不能仅增加超时。[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)

诊断失败时，已经提交的回答仍保存在本机，可以点击“保留原回答，重试分析”。每条失败记录最多重试两次；失败不是学生答错，也不等同于内容判断上的“无法判断”。

答题诊断的提示词保存在 `ankisense/prompts.py`，当前版本为 `v3-rubric-boundaries`。新版先判断是否提供了相关知识，再逐项核对已审核评分要点；正确内容与明确错误混合时指出错误，问候或犹豫语气本身不影响知识判断。每次新分析会记录提示词版本，旧记录不会自动重算。修改该文件后，需要在原服务窗口按 `Ctrl+C`，再运行 `.\start.ps1`；网页刷新后提交新回答。仅刷新网页不会让旧后端加载新提示词。演示模式仍使用有限的本地规则，不能用于验证云端提示词效果。

## 8. 暂时关闭真实 AI

在 `.env` 中将 `AI_MODE=cloud` 改为 `AI_MODE=demo`，保存后重启服务。

这会让之后的操作使用本地演示规则，不会删除已经保存的讲义、卡片和作答记录。演示规则只覆盖原始的三张内置基础题及少量预设表达。

## 验收记录

- 本指南已与当前项目代码和上述官方文档核对。
- 本次没有读取或填写真实 API Key，没有发起真实付费模型请求。
- 文本生成、答题分析和逐页视觉校对需分别验证；一次新作答和一次新生成成功，不代表视觉模型能正确识别讲义原页。
