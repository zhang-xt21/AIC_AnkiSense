# 从讲义中推荐卡片配图

制卡入口默认开启 **自动匹配讲义图片**，可在开始制卡前关闭。模型在生成卡片的同一次请求中判断「无需图片／辅助理解／必须看图」，并指出本卡引用的原文片段；系统仅在这些片段所在页匹配讲义原图，不生成虚构图片。

本地匹配复用 Docling 页缓存，不调用云端模型；找到无歧义的独立图块后，自动发送候选裁图、对应原页以及本卡题目、答案、评分点和引用到当前配置的视觉模型，会消耗 API 额度。检查通过后才把图片保存到卡片，并复用这次视觉结果进行整卡机审，避免再次上传同图。

- **辅助理解**：先排文字机审，配图后台处理；图片不通过时原文字卡仍可学习，通过后附到答案侧并检查新版卡片。
- **必须看图**：等图片通过后放到题目侧，再进行整卡机审；缺图、放错侧或图片来源过期时不能学习、导出或同步。
- **未找到／需要处理**：多幅图难以区分、表格、整页备选、裁剪疑点或模型无法确认时，不自动采纳；显示原因供你手动处理。失败不自动重试。

自动配图不覆盖已有附件，编辑卡片或原文会使正在处理的旧结果失效。后台新增图片形成新的卡片版本，界面保留当前未保存编辑，可通过「载入最新版本」查看。服务重启不自动续跑配图；显式重试接口为 `POST /api/cards/{id}/auto-illustration`，请求 `{"card_version": 1}`。

需要手动选图时，打开「讲义制卡 → 制作卡片」，选择引用了 PDF 原文的卡片，在「讲义配图」中点击 **推荐讲义配图**。这一步在本机分析引用页，不调用云端大模型，也不会把整份讲义上传。

## 手动选图与裁剪

1. 保存卡片的题目、知识概念和引用。引用当前有文字的讲义页即可推荐和采纳图片，不要求先逐页人工校对。
2. 点击「推荐讲义配图」。首次解析要等待本地图块模型处理；已解析过的相同页面会复用缓存。
3. 对照候选图上的页码、推荐理由，确认图意和裁剪范围。推荐只在卡片明确引用的页内查找，最多展示 3 个图或表候选。
4. 图块完整时点「采纳」。需要调整时点「预览 / 调整范围」，在完整原页上拖动框选，或修改四个边界百分比，再点「采纳此范围」。
5. 新图片加入当前未保存的编辑，默认放在答案侧。原有图片会保留，每张卡最多 4 图；可以调整位置、说明和顺序。
6. 点击「保存并检查」。新推荐图先随卡片保存为草稿；已配置云端模型时，系统自动检查最终配图，再检查题目、答案、评分要点和引用。全部通过后显示「机器审核通过」，无需再次人工批准。有疑点时可重裁、更换、移除图片或修改卡片后重新检查。
7. 在「开始练习」检查：题目侧图片作答前可见，答案侧图片在分析完成后的参考答案中查看。导出的 APKG 包自动携带已批准卡片的图片。

## 图片分类、描述与视觉检查（可选）

在候选图下点击 **分类并检查配图**，或在「预览 / 调整范围」中先框选并选择答案侧／题目侧，再点击同名按钮。系统通过 Docling 的图片描述 API 增强阶段，向当前配置的云端模型发送两张独立图片：**实际裁剪图与对应完整原页**，以及已保存的题目、参考答案、评分要点和引用。不会发送整份 PDF。此候选预览检查由按钮触发；普通配图推荐仍在本机运行。图片正式保存到卡片后，还会进入下面的自动审核流程。

使用原有 `AI_MODE`、`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY` 配置，所选服务还必须支持图片输入与 JSON 输出。准备状态只检查配置和环境，不代表供应商一定接受图片。每次未缓存检查最多尝试一次模型请求；失败后由你决定是否重试。

结果包含图片类别、可见内容描述、与题目的关系、裁剪完整性、清晰度，以及题目侧是否泄露答案，分别显示「未发现明显问题」「建议调整」「无法确定」。类别由配置的视觉模型生成，**不是 Docling 原生分类器给出的教学正确率**。候选图预览检查不修改或批准卡片，也不改变 Anki 学习进度；正式卡片的自动批准须通过下文的完整检查。

对“看图回答”的题目，图中的数字或字母可能是作答条件，模型仍可能将它误报为泄题。请结合题目意图核对，不要仅凭这一项删除必要配图。

检查只针对已保存的文字和评分点；先保存这些修改再检查。裁剪框和显示侧可在弹窗直接选择。内容、来源版本、图片范围、显示侧或模型改变后重新检查；完全相同的输入会复用缓存。手动框选会检查新的实际范围，不能沿用旧裁图结果。结果暂存本机 `data/figure-checks`。

每次检查都标明对应的裁剪范围和答案侧／题目侧。采纳推荐范围后，如果把图片改到题目侧，候选区会按新位置检查，原答案侧的结果不会当作题目侧结果显示。另行裁剪的图片与原推荐图范围不同，需在裁剪窗口检查实际采用的范围。

本轮额外试用了官方 Docling 原生 `DocumentFigureClassifier-v2.5`，它可能把循环队列图分为饼图、把顺序栈图分为柱状图。因此原生分类目前保留为实验，未用作自动放行条件；网站使用上述可选的视觉描述和卡片检查。

## 已保存配图的自动审核

上面的候选图检查帮助你决定是否采纳；**配图自动审核**针对已经保存到卡片中的最终图片。配置云端模型后，点击「保存并检查」会自动排队，将相关文字、必要配图与对应原页发送给当前配置的模型，消耗 API 额度。系统先检查尚未通过的配图，再检查整卡；可在「检查结果」查看进度，不需要逐张点击图片检查。仍可主动使用「自动检查配图」单独检查或重试，界面会说明发送范围。打开卡片或读取旧状态不会调用模型。

系统先在本机检查图片确实来自当前 PDF 的有效引用页、排除明确的校徽和页角装饰后仅有一个独立正文图块，且最终 PNG 与记录的裁剪范围一致。正文中的第二张图、表格或公式区域仍会留下疑点；不会只根据排名靠前的候选图判断。引用页可以是「已提取」或「已人工核对」，不强制逐页确认。通过这些检查后，视觉模型还需确认图与卡片内容相关、裁剪完整、清晰，并且题目侧图片没有提前泄露答案，才会显示「配图机审通过」。不满足条件时显示待处理状态及原因。手动上传、整页备选、来源不明或有疑点的图片目前不在自动放行范围，可人工核对后使用备用批准入口；辅助理解的图片可以留空，必须看图的题目需先补齐题目侧图片。

单张配图通过还不等于整卡通过。所有已保存配图及题目、答案、评分要点和引用全部通过当前版本检查后，整张卡片自动批准，可学习、导出和同步到 Anki。调用失败或仍有疑点时保留为待处理，可修正后重试，也可展开「自行核对并处理」人工批准。演示、粘贴文本等没有真实 PDF 的材料不在整卡自动批准范围。

修改卡片、引用、原文或附件后，旧批准失效，需针对新版本重新检查；只保存相同原文不会让已有批准失效。一次自动通过不能证明配图一定正确，仍需按[自动配图审批的离线验收](自动配图验收方法.md)用不同讲义的人工标注样本测错放率。

## 怎样理解推荐

- **同页候选**：图块与卡片引用位于同一 PDF 物理页；可能按图注、附近文字与题目/引用的文字匹配排序。它不代表系统已经理解图中的关系，也不保证就是题目需要的图。
- **整页原图备选**：保留完整讲义页，方便手动裁剪。它不会被算作找到独立示意图；没有合适图时，卡片可以继续只用文字。
- **图块识别未完成**：本地模型没有就绪、解析失败或超时。原文校对、已有配图仍可使用；可以从整页原图框选，稍后重试推荐。

框选时保留有关联的线条、箭头、坐标轴、图例和文字。整页讲义常含答案，默认放答案侧；确实需要看图作答时，再改到题目侧，并检查是否提前泄露答案。

自动候选会根据带位置的图注、公式和与题目相关的邻文保守扩大范围，并说明扩入了什么。为避免跨到其他图块或无关栏，不能安全组合时会保留疑点提示。仍可能带入旁边的半个字、页脚装饰或邻图残片；例如公式与学校页脚被解析成一个文字块时，扩大范围也会带入页脚。遇到这类情况可手动调整或运行视觉检查。推荐不等于内容已审核。

修改题目、知识概念或引用后，需要先保存再重新获取推荐。原文校订、卡片版本或原 PDF 变化后，旧推荐会被拒绝采纳，防止图片与来源错位。旧配图与历史答题快照不会因此被覆盖。

## 本地数据和组件

业务数据继续保存在 `data/ankisense.sqlite3`。推荐任务、图块缓存及来源版本保存在其中；候选预览位于 `data/figure-previews`，解析缓存位于 `data/figure-cache`，正式采纳的 PNG 位于 `data/media`。图片来源记录包含原 PDF 摘要、物理页码、校对版本、裁剪边界和解析器版本。

Docling 使用独立 `.venv-docling` 环境，避免改变网页后端已有依赖。运行时使用本机模型，原文 OCR 与校对流程仍使用原有组件。Docling 用于图块和表格的版面识别；正式配图从 PDF 原页渲染后裁剪，保留矢量线条与箭头。

本机已安装 Docling 2.130.0 和官方 Heron 布局模型，模型保存在 `data/docling-models`。模型固定到 `8f39ad3c0b4c58e9c2d2c84a38465abf757272d8`，运行依赖已锁定。PDF 读取采用 Docling 官方 PDFium 后端，支持本项目的中文路径；图块推理使用 CPU，不需要额外的云端 API Key。

当前 AI 出题与答题分析仍只处理文字。需要根据图片中的数值、边或箭头判断答案时，请将必要条件和评分依据写入题目与评分要点。

## 在另一台电脑安装组件

网页基础环境安装完成后，在项目目录执行：

```powershell
.\tools\setup_docling.ps1 -Python .\.venv\Scripts\python.exe
```

脚本会创建独立的 `.venv-docling`，安装锁定依赖并下载本地布局模型。首次安装需要联网；日常推荐使用已下载模型，在本机离线推理。安装后按原来的 `start.ps1` 启动网页即可，不需要另开一个 Docling 网站或填写额外 API Key。

安装脚本包含较长下载超时、重试与断点续传。默认使用官方 PyPI，也可通过 `-IndexUrl` 指定可信软件源。

单个任务最多分析 8 个明确引用页，解析子进程上限 300 秒，超时会转为整页备选。点击取消可停止发布本次推荐结果；正在执行的解析会在结束或超时后释放资源。
