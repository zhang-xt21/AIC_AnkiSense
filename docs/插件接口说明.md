# Anki 插件接口 v1

AnkiSense 后端接口和可复用 Python 客户端已提供图文卡片读取、版本检查及回答提交能力。最小桌面同步插件也已实现，见[使用说明](Anki同步插件使用说明.md)：当前 Anki 界面支持连接、选牌组和同步图文卡片，回答输入窗口仍待后续接入。接口不会修改 Anki 的复习排期、自动选择评分按钮或删除已有笔记。

## 本机连接

后端仍通过 `start.ps1` 启动，默认 `http://127.0.0.1:8765`。在项目目录初始化插件连接：

```powershell
.\.venv\Scripts\python.exe tools\plugin_connection.py init
.\.venv\Scripts\python.exe tools\check_plugin_connection.py
```

连接文件位于当前业务数据目录的 `plugin-connection.json`（默认 `data/plugin-connection.json`）。文件包含 `protocol_version`、稳定 `server_id`、本机 `base_url`、随机 `token` 和 `enabled`；这是插件连接凭据，与云端模型的 API Key 无关。工具只输出配置状态和路径，不输出 token。以后插件读取该文件或导入连接配置即可，模型 API Key 始终由后端保存。

如使用不同端口，初始化时加 `--base-url http://127.0.0.1:端口`；使用其他数据目录时加 `--data-dir 路径`。地址只允许本机 `127.0.0.1` 或 `localhost`。连接配置实时读取：

```powershell
.\.venv\Scripts\python.exe tools\plugin_connection.py status
.\.venv\Scripts\python.exe tools\plugin_connection.py rotate
.\.venv\Scripts\python.exe tools\plugin_connection.py disable
```

`rotate` 更换 token，旧凭据立即失效，`server_id` 保持不变；`disable` 禁用插件接口，再次 `init` 可以启用。不要把连接文件放进卡片模板、牌组包、日志或提交到版本库。它允许访问本机学习内容和发起已确认的模型分析。

## 请求约定

统一前缀：`/api/plugin/v1`。全部接口要求：

```http
Authorization: Bearer <本机连接文件中的 token>
X-AnkiSense-Client: <本 Anki 配置固定保存的随机标识>
```

客户端标识应由插件为每个 Anki 本地配置生成并持久保存，例如随机 UUID；允许 8–80 位字母、数字、下划线和连字符。不使用姓名或学号，不在每次请求时重新生成。此标识隔离答题请求和结果；连接 token 才是访问凭据，当前服务仍面向单人本机使用。

网络请求放在 Anki 的后台操作中，避免界面卡住；UI 更新回到主线程。以后写入笔记和媒体应使用 Anki 的 Collection API，而不是直接写 Anki 数据库。参见 [Anki 后台操作](https://addon-docs.ankiweb.net/background-ops.html)和 [Collection API](https://addon-docs.ankiweb.net/the-anki-module.html)。

OpenAPI 请求结构可从本机 `/openapi.json` 获取，其中已标注 Bearer 凭据和客户端标识。

| 方法与路径（省略统一前缀） | 用途 |
|---|---|
| `GET /status` | 协议、服务实例、能力、当前 AI 模式和超时建议 |
| `GET /cards` | 完整同步清单，仅包含当前可用的已批准卡片 |
| `GET /cards/{id}?expected_hash=...` | 获取指定版本内容、Anki 字段、模板和媒体清单 |
| `GET /media/{id}?sha256=...` | 下载清单指定的 PNG 图片，必须带预期摘要 |
| `POST /attempts` | 提交当前版本的回答并返回分析结果 |
| `GET /attempts/{id}` | 查询本客户端的回答与反馈，包括处理中状态 |
| `POST /attempts/{id}/retry` | 对失败分析明确重试，最多两次 |

`GET /status` 返回 `application: "AnkiSense"`、整数 `protocol_version: 1`、`server_id`、`capabilities`、`ai` 和 `limits`。首次连接核对协议和实例，不能把不同数据目录的同步记录混用。能力声明明确包含 `sync_mode: "full_manifest"`、`schedule_write: false`、`automatic_deletion: false`；当前回答诊断仍是文字流程，不发送卡片图片。

## 卡片和配图同步

`GET /cards` 返回完整的：

```json
{
  "protocol_version": 1,
  "server_id": "as-示例标识",
  "complete": true,
  "snapshot_id": "本次完整清单的SHA256",
  "cards": [
    {"id": "卡片ID", "version": 2, "guid": "稳定AnkiGUID", "content_hash": "内容SHA256", "url": "本机详情地址", "media": []}
  ],
  "excluded": []
}
```

`cards` 不含草稿或已拒绝卡片；已批准但来源过期、引用无效或图片缺失的卡片放入 `excluded`，附原因。`complete` 表示全量枚举完成，不是增量变更流。缺席或排除都不是删除 Anki 笔记的指令；初版插件应提示，保留已有笔记和复习记录。接口失败或收到不完整清单时不要应用任何删除。

卡片详情字段：

- `id / version / guid / content_hash`：业务身份、修订、与 APKG 一致的 Anki GUID、内容摘要。
- `fields / field_order`：已安全转义的 Anki 字段值和固定顺序。
- `model`：模型 ID、名称、字段、标准卡片模板、CSS、排序字段；`templates[].ordinal` 固定为 0。
- `deck / tags`：目标牌组信息与标签。
- `source`：材料编号、文件名、演示标记、原文引用、物理页码及可用的来源修订号。粘贴文本或演示的页码是片段编号。
- `images`：图片编号、`question/answer` 显示侧、说明。
- `media`：图片 `id / filename / content_type / sha256 / size_bytes / width / height / url`。

卡片详情请求带清单中的 `expected_hash`；卡片变化会返回 409，客户端应重新取清单。`version` 用于答题一致性检查，`content_hash` 还覆盖图片、来源和模板变化，适合决定是否需要更新本地笔记。

同步建议顺序：

1. 校验 status 的协议与 `server_id`，读取完整清单。
2. 对新增或内容摘要变化的卡片，带 `expected_hash` 获取详情。
3. 下载所需媒体，校验字节长度和 SHA256。全部准备好以后，再进入 Anki 的写入操作；下载失败不写半张卡片。
4. 使用既有模型 ID `1786831001`、牌组 ID `1786831002`、稳定 GUID 及 `NoteID` 定位笔记。字段保持 `NoteID, Question, Answer, Concept, SourceFile, PDFPage, SourceQuote, PracticeURL`；媒体沿用 `ankisense-img-<32位ID>.png`。这样可与同一业务卡片的 APKG 身份对应。
5. 若 Anki 已有同身份笔记，更新它的内容；不要重建卡片或写调度字段。发现模型结构不一致、多重匹配、或用户在 Anki 内修改了内容时，显示冲突，不盲目覆盖。
6. 最后记录该配置的 `server_id / card_id / guid / version / content_hash` 映射及上次同步字段，用于后续更新和本地编辑冲突检测。

`addons/ankisense_sync/` 现已实现 Anki 中的查找、写入、撤销与冲突提示；同步前下载并验证整批内容，然后通过官方 Collection API 写入。PDF 导入制卡接口和 Anki 内回答窗口尚未接入此版插件。

## 回答与反馈

插件应在学生主动提交时生成一个 `request_id`，保留回答文本和该 ID，直到确认获得结果。请求示例：

```json
{
  "card_id": "业务卡片ID",
  "card_version": 2,
  "answer": "最后放进去的元素最先出来",
  "request_id": "本次提交固定的UUID",
  "allow_cloud": false
}
```

云端模式下，非空回答需要先向学生说明会发送题目、审核后的参考答案、评分要点、关联原文和回答，再传 `allow_cloud: true`。同步卡片、下载图片、查询反馈不会调用模型。空白回答记为 `unanswered`，不调用模型。

提交前检查卡片版本、批准状态、引用归属及来源校对状态。旧版本或失效来源返回 409；插件保留输入，提示同步后重新作答。成功接受后保存题目和来源快照；后续原文修改不会改写此次历史反馈。

返回沿用网页答题记录：`id`、`status`、`answer`、`diagnosis`、`error`、`card_snapshot`、`source_snapshot`、`remediation`、`retry_count` 等，另带 `origin: "anki"` 和 `client_id`。`status` 为 `pending/completed/failed/unanswered`；只有 `completed` 的 `diagnosis` 是有效诊断。诊断包括 `verdict`、缺少/矛盾的评分点、回答片段、原文依据和理由。失败是调用失败，不等于回答错误。

`request_id` 在同一客户端内幂等：相同卡片版本、相同回答、相同提交 ID 会复用记录，不重复付费；复用 ID 但内容或版本改变返回 409。不同客户端的相同 ID 不冲突。返回记录里的 `request_id` 是后端加客户端命名空间后的内部键；重放原提交时仍使用插件最初生成的 ID。

POST 通常等待分析结果。插件使用后台请求及足够超时（读取 status 的建议值）；网络中断后保留原回答与 ID，重放同一提交或查询已有 attempt。服务会继续已接受的分析；服务重启中断时，记录变为可重试失败，不自动再次调用模型。

对 `failed` 记录，明确重试时发送：

```json
{"expected_retry_count": 0, "allow_cloud": true}
```

`expected_retry_count` 必须是刚读取的失败记录中的次数。相同次数的并发/重复重试仅有一个能启动；旧次数返回 409。每个回答最多重试两次。重试网络中断后先 GET 当前记录确认状态，不自动开启下一次重试。重试使用原快照，不套用后来改动的题目。

AI 反馈用于帮助理解，插件应让学生自己决定 Anki 的 Again/Hard/Good/Easy。接口不提供自动填写这些评分的操作。

## 错误处理

插件接口业务错误采用：

```json
{"detail": {"code": "card_changed", "message": "卡片已变化，请重新读取同步清单。"}}
```

常见状态：401 凭据失效；400 客户端标识错误；404 内容不可用或反馈不属于此客户端；409 版本、内容、重试次数冲突或需要云端确认；422 请求格式错误；503 插件连接未启用。插件请求格式错误不会回显学生回答。旧网页接口继续保持原行为；全局跨来源拒绝等错误仍可能返回字符串 detail，客户端兼容此格式。

客户端不会自动跟随重定向、使用系统代理转发本地凭据或自动重试。连接文件变化后应重新创建客户端，特别是 token 轮换后。

## 可复用客户端

`examples/anki_plugin_client.py` 仅依赖 Python 标准库，可复制到未来插件包中。先用不调用模型的连接检查：

```python
from examples.anki_plugin_client import PluginClient

client = PluginClient.from_connection_file(
    "data/plugin-connection.json", client_id="example-anki-profile-001"
)
status = client.status()
catalog = client.catalog()
for summary in catalog["cards"]:
    card = client.card(summary["id"], expected_hash=summary["content_hash"])
    for asset in card["media"]:
        png = client.media(asset["id"], asset["sha256"])
        # 后续插件通过 Anki media API 保存，使用 asset['filename']。
```

上述示例只读取；正式插件应将示例 client_id 替换为为当前配置生成并持久保存的随机 UUID。答题使用 `submit_answer(...)`，查询使用 `attempt(id)`，明确重试使用 `retry_attempt(id, expected_retry_count, allow_cloud=...)`。不要把连接 token 或已渲染的答案注入学生作答前的题面脚本。
