# 自动制卡：接口与验收

当前默认入口是 `POST /api/material-imports`：选择 PPT、PPTX 或 PDF 后，后台自动解析、提取知识、生成卡牌并对照原页检查，网页自动显示结果。逐页确认、手选片段和人工批准属于可选高级流程，不是默认导入的前置步骤。Anki 插件仍使用现有 v1 接口。

## 默认自动导入 API

| 方法与路径 | 输入 | 输出/行为 |
| --- | --- | --- |
| `POST /api/material-imports` | `multipart/form-data` 的 `file` 字段，支持 `.ppt` / `.pptx` / `.pdf`，最多 50 MB | 保存文件并返回后台导入任务；相同文件及扩展名重用已有任务 |
| `GET /api/material-imports` | 无 | `{imports: [...]}`，包含导入状态及关联制卡任务 |
| `GET /api/material-imports/{id}` | 无 | 当前导入状态、解析进度、材料编号及关联任务 |
| `GET /api/auto-card-jobs/{job_id}` | 无 | 制卡阶段、批次进度、卡牌编号、处理说明及错误 |

导入任务包含 `id`、`filename`、`status`、`message`、`progress`、`document_id`、`job_id`、`error`、创建与更新时间。制卡启动后还包含 `job`，公开状态与消息跟随该制卡任务。前端根据 `/api/state` 返回的卡牌持续更新结果，刷新后可恢复同一导入任务。

整份材料最多 500 页、100 万字；自动导入以 `autonomous=true`、`image_mode=source_page`、`max_cards=600` 启动制卡。PPT / PPTX 需要本机 PowerPoint 或 LibreOffice 转成 PDF 以保留原页图表；PPTX 同时提取原生文字。PDF 使用文字层或本机 OCR。模型必须支持图片输入，默认流程会向已配置模型发送原文和对应原页。

自动流程不要求先把整页原文标成人工确认。知识提取时结合文字和原页，再由独立调用对照原页检查每张卡牌的问题、答案、评分点和引用；程序另做逐字引用、结构及重复检查。有疑点时最多尝试一次内容修正并重新检查。多张卡牌可以合并在一次检查请求中，每张仍须返回有效、唯一且完整的对应结论。

通过检查的卡牌记录为 `status=approved`、`approval_method=automatic`，可直接练习、导出和同步；未解决疑点的卡牌保留 `status=draft` 与原因，可以阅读和编辑，但不作为已就绪卡牌使用。卡牌的自动批准不设置页面人工确认记录，也不表示整个来源页已被纠正或人工审核。

`source_page` 把引用的完整讲义原页附在答案侧，作为可追溯的来源图片；它不表示已经自动识别并精确裁剪出最合适的独立图形。自动任务设 `image_mode=off` 时不保存原页附件，但知识提取和卡牌检查仍使用原页图片。

目录、课程安排和单独的视频文件名按规则跳过。模型调用失败最多自动重试一次；仍失败的批次保留原因并继续其他内容。已完成批次和卡牌保存到本机；相同配置下，未完成的自动任务可在服务重启后继续。来源变化使任务过期，不能用旧检查发布新内容。任务完成或达到卡牌上限不表示覆盖了讲义的全部知识点。

## 制卡任务与可选高级 API

| 方法与路径 | 输入 | 输出/行为 |
| --- | --- | --- |
| `POST /api/documents/{document_id}/auto-card-jobs` | `autonomous` 默认 `false`；`max_cards` 默认 30，自动任务 1–600、高级手动任务 1–60；`image_mode`：`off` / `recommend` / `checked` / `source_page`；`source_mode`：`manual` / `visual` | 创建任务；相同材料版本、模型、提示和选项重用已有任务；默认导入通过此接口使用自动模式 |
| `GET /api/documents/{document_id}/auto-card-jobs` | 无 | `{jobs: [...]}`，最新任务在前 |
| `POST /api/auto-card-jobs/{job_id}/retry` | 空对象 | 按来源和配置校验继续未完成部分；已保存批次不重复写卡 |
| `POST /api/auto-card-jobs/{job_id}/cancel` | 空对象 | 停止继续发布，已保存卡牌保留 |
| `POST /api/cards/{card_id}/auto-quality-check` | `expected_version`：已保存卡片版本 | 高级流程的文字重新检查；要求来源可用，版本冲突或来源过期返回 409；不会重新执行自动导入的原页批准政策 |
| `POST /api/documents/{id}/pages/{page}/calibration` | `revision`，可选 `force` | 可选整页校准：两次原页读取及修正政策；自动采用或返回待确认差异 |
| `GET /api/documents/{id}/pages/{page}/calibration` | 无 | 当前来源版本的校准报告；旧版本报告不作为当前结果 |

高级手动流程使用 `autonomous=false`。其默认 `source_mode=manual` 只使用人工确认或符合整页机器核对政策的来源；可主动选择 `source_mode=visual`，发送待确认原页做整页校准，通过的页面继续制卡，其余等待确认。该模式生成的卡牌均为草稿，需要人工批准。它的整页确认要求与默认自动模式的卡牌自身检查是两套政策。

高级流程的 `image_mode=recommend` 仅准备本机候选；`checked` 会向模型发送候选裁图和对应原页，通过检查后保守附图。默认自动导入使用 `source_page`，不依赖 Docling 独立图块推荐。`source_mode` 选择用于高级手动流程；`autonomous=true` 直接执行卡牌自身原页检查。

## 任务、卡牌与证据字段

任务保存在 SQLite 的 `auto_card_jobs` 集合中。公共结果包括：

- `id`、`document_id`、`options`、`created_at`、`updated_at`。
- `status`：`pending`、`running`、`awaiting_confirmation`、`completed`、`failed`、`cancelled`、`outdated`；`awaiting_confirmation` 用于高级手动流程。
- `stage`：`source`、`knowledge`、`generation`、`quality`、`images`、`complete`。
- `progress.completed/total`：已保存检查点的原文批次数，不是模型请求次数或正确率。
- `card_ids`、`knowledge_count`、`skipped_count`、`issues`、`message`、`error`。
- `calibration`、`pipeline_version`、`prompt_version`：筛查及处理版本信息。

生成卡牌沿用现有 CardDraft 字段，并记录：

- `auto_job_id`、批次作用域内的 `knowledge_id`；知识点和证据保存在任务检查点。
- `auto_quality`：`scope`、`verdict`、`issues`、`supported_point_ids`、`card_version`、`source_block_ids`、提示版本、检查时间及修正次数。高级文字检查的范围是 `text`；自动原页检查的范围是 `text_and_original_page`。
- 自动批准卡牌的 `automatic_evidence`：政策 `automatic-card-visual-v1`、原页检查标记、卡牌内容摘要、引用块摘要及原页图片摘要，用于绑定当前卡牌和来源。
- `image_result`：附图状态、原因或高级推荐/检查编号；原页附件在 `images` 中标记为答案侧。

自动批准有效性要求卡牌仍为当前版本、来源未失效、检查为无疑点、检查范围匹配，且政策、卡牌摘要和引用块摘要等记录一致。修改卡牌文字、评分点、引用或图片后，旧自动检查不再用于新版本。只返回模型自评或单独的文字检查，不能成为自动原页批准记录。

整页校准通过后保存 `status=auto_verified`，不填写人工 `reviewed_at`。该政策要求两次转录一致且没有不确定项；数字、单位、否定、英文标识和公式符号不变；不涉及公式/多栏风险或大范围重写；实际修改还需原图局部整行复识别支持。修改可引用文字时建立新来源版本，并保留原始 OCR、修正差异和校准报告。

## 验收与限制

离线 API 测试覆盖自动上传、超过旧 30 页限制、原生幻灯片顺序、目录筛选、分批保存、疑点不冒充通过、局部失败继续、去重、重启恢复、来源并发修订、模型设置锁、自动批准有效性与导出。高级流程另覆盖整页视觉校准、人工确认、文字重新检查及保守候选附图。模拟模型只验证流程约束。

`npm run test:browser:automatic-import` 覆盖选择文件即启动、自动进入结果、刷新恢复、卡牌陆续出现以及窄屏布局；`npm run test:browser:auto-cards` 覆盖可选高级任务控制和检查。完整网页回归入口为 `npm run test:browser`。

固定整页校准案例和本机 OCR 基线可用 `tools/evaluate_source_calibration.py` 重现；真实模型的小规模检查记录见 [导入后自动制卡验收](导入后自动制卡验收.md)。程序通过数和少量模型样本不能推算整份讲义准确率。固定人工标注样本上的 OCR 修正正确率、疑点漏检/误报、知识覆盖、重复、配图质量和人工修改时间仍需单独评估。

当前配图采用完整原页，独立图形的自动精确裁剪尚未验收；自动检查仍可能漏错。默认流程的目标是减少操作并提供可追溯卡牌，不保证每页有卡牌或所有知识点均被覆盖。
