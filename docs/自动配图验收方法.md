# 自动配图审批的离线验收

自动审批的目标是减少逐张核图，但视觉模型的 `pass` 不能代替人工真值。先用人工标注的数据检验**最终保存的卡片与裁图**，再决定是否向真实用户开放自动通过。本验收工具只读取本地 JSONL，不调用模型、不读取 PDF 或用户数据库。

## 怎样准备样本

一行表示一个「卡片版本＋最终配图＋显示侧」组合。审核者对照最终裁图、原页、题目和答案，独立标注图片是否合适。建议先不看系统结论；有争议的样本由第二人复核。每次更换模型、提示词或审批规则后，重新生成对应版本的系统决定，不要把不同版本混在同一份结果里。

先用至少 **50 个开发集案例**调整规则，再冻结规则，用**不同 PDF** 制作留出集。留出集应覆盖至少 3 份 PDF，并获得至少 **150 个 `auto_pass` 案例**；同时保留系统未放行的案例，用于计算覆盖率。让样本包含单图、多图、公式、表格、扫描页、裁掉箭头或标签、模糊图、题目侧泄题等情形。开发集和留出集不能来自同一份原始 PDF，即使文件名不同也不应重复使用；`document_id` 最好使用原始 PDF 的稳定摘要。

每个案例使用以下字段，额外的人工备注可以保留，但无需放入完整讲义、图片或密钥：

| 字段 | 含义 |
| --- | --- |
| `case_id` | 此次卡片＋图片＋版本的唯一 ID；不要在两行复用 |
| `document_id` | 原始 PDF 的稳定 ID，同一 PDF 的所有案例必须在同一个数据集分组 |
| `split` | `development` 或 `holdout` |
| `category` | 主要情形，例如 `single_diagram`、`multi_figure`、`formula`、`table`、`scan`、`manual_crop` |
| `human_label` | 人工认为配图合适为 `correct`，错图、重要内容缺失或题目侧泄题为 `wrong` |
| `severe_error` | 仅在 `wrong` 时可为 `true`；表示误导概念、错图、关键标注缺失或明显泄题等严重问题 |
| `decision` | 自动检查接口的最终 `status`：`auto_pass`、`needs_review`、`attention` 或 `unchecked` |
| `current` | 接口结果是否属于当前版本；`auto_pass` 必须为 `true`，尚未检查的案例可为 `false` |
| `current` | 自动检查接口返回的当前性；`auto_pass` 必须为 `true`，未机审或本地门槛拦下的案例可为 `false` |

只把 `auto_pass` 视作系统自动放行。若文字、原文、图片范围或显示侧已变化，先重检，再记录新状态；工具会拒绝 `current=false` 的旧 `auto_pass`。尚未机审的 `unchecked` 和本地门槛直接拦下的 `needs_review` 可以是 `current=false`，仍计入覆盖率分母。不要只收集 POST 成功的案例，否则会高估自动通过率。

合成样例在 [`examples/image_approval_eval_synthetic.jsonl`](../examples/image_approval_eval_synthetic.jsonl)。它用于演示格式，**不是实际模型测试数据，也不代表任何准确率**。真实标注文件应留在本机个人数据目录，不要提交包含课程内容的记录。

## 运行报告

在项目根目录运行：

```powershell
python .\tools\evaluate_image_approval.py .\examples\image_approval_eval_synthetic.jsonl
python .\tools\evaluate_image_approval.py .\examples\image_approval_eval_synthetic.jsonl --json
python .\tools\evaluate_image_approval.py .\your-local-labels.jsonl --check-release
```

报告给出整体、开发集、留出集、各类别、留出集内各类别和各 PDF 的案例数，以及：

- **自动通过覆盖率** = `auto_pass` 数 / 全部案例数；
- **错放率** = 人工标为 `wrong` 但系统 `auto_pass` 的数量 / `auto_pass` 数；
- **严重错放数** = 上述错放中人工标为 `severe_error=true` 的数量；
- **错误案例逃逸率** = 错放数量 / 所有人工标为 `wrong` 的数量。

没有自动通过案例时，错放率显示 `N/A`，不能误读成 0%。工具会拒绝重复 `case_id`，以及同一 `document_id` 同时进入开发集和留出集。

`--check-release` 是**试点门槛**：开发集至少 50 例；留出集至少 150 个自动通过案例，来自至少 3 份 PDF，且至少包含 30 个经人工确认的错图或缺图案例；留出集严重错放为 0、普通错放率不超过 1%。负例也应覆盖可能被自动放行的简单示意图，避免只用明显模糊的图凑数。退出码 0 表示满足这些样本条件，1 表示未满足。即使达到门槛，也只说明这批样本的表现，不保证新讲义上的配图一定正确。先按类别核查报告；某一类明显不可靠时，应让该类继续人工确认，而不是被总体数字掩盖。

上线初期建议保留人工反馈入口，定期抽检自动通过的卡片。发现严重错放时先暂停该类自动通过，修正规则并使用新的留出 PDF 复验。
