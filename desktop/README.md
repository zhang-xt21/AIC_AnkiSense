# AnkiSense Windows 桌面版

Electron 只负责本地服务、原生窗口和窗口控制。网页与后端共用 `ankisense/` 的实现；默认选择 PPT/PPTX/PDF 后自动处理，卡牌结果页可查看、编辑、练习和导出。张数、配图与补充制卡位于高级选项。

0.1.18 打包当前制卡与审核规则、受限公式JSON定界符修正、自动拆分补做和失败隔离。过载目标先拆成有来源依据的子目标，再按数量预算制卡和复审；未通过的新候选留在任务待处理记录，不进入学习卡库。剩余拆分目标超出数量预算时保留待补做，单轮拆分和单卡修复有上限。卡片结果默认只显示可学习卡，旧草稿可主动查看；不批量删除历史卡片或标注。详情见[过载卡自动补做与失败隔离](../docs/history/过载卡自动补做与失败隔离.md)。

自动制卡分别显示成功、失败、部分完成和待处理批次，可展开「待处理记录」查看页码与具体原因。模型引文仅有可对齐的排版空白差异时，会恢复成原文中的连续片段后再校验；数字、标点、否定词和片段编号仍须一致。同批的有效知识点保留，补跑只处理未完成项；保存的候选能本地恢复时先复用，否则把失败原因交给模型定向修正。历史任务不会因升级而自动调用模型，需主动点击继续；候选仍须经过质量审核才可自动批准。

0.1.10 修复桌面标题栏拖动区域遮住配图弹窗按钮的问题。弹窗打开期间暂停标题栏拖动，关闭后恢复；裁剪窗口滚动时保留顶部「取消」，也可以按 Esc 退出。取消只丢弃当前框选，不采纳图片，不修改已保存卡片。

0.1.11 移除独立版面解析环境。配图区提供引用页缩略图与裁剪，坐标和检查详情默认折叠；图片检查直接使用配置的模型 API。准备原图不调用模型；图片检查单次请求、失败主动重试。历史配图保留，Anki 插件无需更新。

0.1.12 在卡牌结果页增加关键词、可学习／待处理／检查中与配图筛选；练习页可选择讲义、搜索题目或知识点，并按配图筛选。练习进度、完成分类、上下张与最近记录均按当前范围显示，切换条件保留回答草稿。筛选在本机完成，不调用模型。

0.1.13 修复工作台顶部练习按钮沿用上次讲义的问题：优先练习当前已批准卡片，否则选择本讲义的可学习卡片；无可学习卡片或当前编辑未保存时禁用。桌面版下载提示适配原生窗口，隔离测试验证实际下载文件。

0.1.14 打包新审核标准：审核回执与诊断校验失败时定向重试，审核协议失败保留原卡、不误作内容修复；增加独立作答检查，拦截题目未问却强制要求的表示法；空余配额回填已验证的剩余知识点。旧机器批准缺少新检查记录时需重新机审，才能学习、导出与同步。拟自动放行通常增加两次模型调用；同材料完整重测的结果与限制见 [新材料问题修复与回归](../docs/history/新材料问题修复与回归.md)。

## 开发运行

0.1.19 将批量操作改为「删除本材料及卡片」，同步移除材料选项、导入及制卡任务记录、本地练习与原文记录。0 张卡片的材料也能删除；单张删除继续保留材料。已同步的 Anki 副本不受影响。

0.1.17 携带 KaTeX 0.19.1 与本地字体。卡片、预览、练习与反馈支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`；编辑框保留源码，无效公式显示原文。此版本增加显示能力，不改动 OCR 识别或 Anki 卡片模板。

0.1.16 增加引用补识别：失败知识点先做括号与排版对齐，有可靠文字坐标时只复识别一次相关区域；仍无法匹配再用当前模型配置做一次裁图转录。补充证据单独保存并绑定原页版本，不覆盖原 OCR，不等于整卡审核通过。失败尝试缓存，同一任务同一引用不循环调用；无可靠坐标、转录有疑点或仍不匹配时保留待处理。支持图片的模型接口方可使用视觉兜底。

先在根目录创建 `.venv` 并安装 `requirements.lock.txt`，然后在 `desktop/` 执行：

```powershell
npm ci --cache ../.ui-checks/npm-cache
# 若当前 npm 阻止依赖安装脚本，用锁定的 electron 安装器补齐二进制：
node node_modules/electron/install.js
npm start
```

默认检查 `http://127.0.0.1:8765/health` 的应用标识、API 与客户端版本，以及 Anki 向导、模型验证、切换模型续跑和大文件导出能力；仅复用版本一致的兼容服务。其他版本的服务占用端口时提示退出，不会静默连接到旧界面。没有服务时启动项目 `.venv` 后端。界面顶部显示后端版本。

- `npm run start:dev`：只连接已运行的兼容服务。
- `npm run start:packaged`：强制启动自己的服务，端口已占用时提示关闭旧服务。
- 同一用户配置目录只运行一个桌面实例。关闭窗口只停止本实例创建的后台进程，复用的服务继续运行。

安装版把数据保存在 Electron 的用户数据目录下的 `data/`，不写安装目录。启动失败会显示可读提示，诊断日志位于用户数据目录的 `startup.log`。

## 连接 Anki

在「导出至 Anki」展开连接向导：检测或选择 Anki → 退出 Anki 后安装并配对插件 → 打开 Anki 等待连接回执 → 在 Anki「工具 → AnkiSense · 同步卡片」选择牌组并同步。安装包包含插件文件，不包含 Anki 主程序；没有 Anki 可通过向导前往官网安装，也可继续独立学习或导出 APKG。

「打开 Anki」以正常可见方式启动程序；若 Anki 已在运行，则尝试恢复所选 Anki 的隐藏或最小化窗口并切到前台。没有找到可显示窗口时会提示重试，不把“进程存在”当作“窗口已显示”，也不会重复启动另一个实例。

首次需启动一次 Anki 初始化资料。自定义资料位置可选择含 `prefs21.db` 的根目录。向导只更新本插件并备份旧文件，不打开学习数据库；仅记录本机连接文件路径，不复制模型密钥。插件心跳有效期为 90 秒，安装成功不会显示已连接。同步结果来自插件完成写入后的计数回执。

## 配置模型 API

在「模型设置」填写 Base URL、模型名和 API Key，先保存，再点击「验证连接」。没有正在制卡的任务时，仅保存不会调用模型；验证只发送一次固定短文本，不发送学习材料。界面显示验证状态、耗时和失败原因，修改配置或重启服务后回到未验证状态。文字与 JSON 测试通过不代表图片能力已验证。

更换服务商须提供新密钥或清除旧密钥；密钥留空会保留同一服务商的已有配置。404 提示检查接口地址和模型名，401/403 提示检查密钥与权限，限流和超时需要主动重试。界面不回显密钥，安装包不包含开发机的模型配置。

默认勾选「保存后用新模型继续当前制卡」。保存有效云端配置时，当前制卡任务先停止旧请求，再用新配置继续未完成部分，已保存的卡片和任务 ID 保持不变。准备中的讲义会使用新配置；历史失败、完成或手动取消的任务仍需主动继续。续跑会产生模型请求和费用。保存失败时不会使用未保存的新配置，任务会停留在可继续状态；保存成功但恢复失败时会单独提示，到结果页处理即可。独立答题、图片检查等工作运行时，仍需等待完成。

## 构建独立后端和安装包

在 `desktop/` 执行：

```powershell
../.venv/Scripts/python.exe -m pip install --cache-dir ../.ui-checks/pip-cache -r requirements-build.txt
npm ci --cache ../.ui-checks/npm-cache
node node_modules/electron/install.js
npm run build:backend
npm run pack     # Windows 可运行目录：dist/win-unpacked/
npm run dist     # NSIS 安装包：dist/AnkiSense Setup *.exe
```

`pack` 和 `dist` 都会先重建 Python 后端，避免安装包误用旧源码。`build-backend.ps1` 把 PyInstaller 缓存限制在忽略的 `desktop/build/` 中。后端包含静态资源、`addons/ankisense_sync/` 插件、PowerPoint 转换脚本、RapidOCR 模型与 ONNX Runtime DLL。`electron-builder` 把它复制到安装程序的 `resources/backend/`。不打包开发数据库、用户设置、API Key 或 `.env`。

PPT/PPTX 转 PDF 仍需要机器安装 PowerPoint 或 LibreOffice，缺少时请先另存为 PDF。基础后端包含 PDF 识别与 OCR；讲义配图直接使用 PDF 引用页原图，可框选裁剪或上传截图；图片机审直接连接配置的模型，无需额外版面解析环境。

当前未配置代码签名证书。正式分发前还需在干净 Windows 环境检查安装、卸载、Office/LibreOffice 转换、真实 OCR 和升级后数据保留；通过开发窗口测试不等于这些安装验收全部完成。

若下载需要本机代理，只设置当前 PowerShell 进程变量，不修改系统代理：

```powershell
$env:HTTP_PROXY = 'http://127.0.0.1:7892'
$env:HTTPS_PROXY = 'http://127.0.0.1:7892'
$env:ELECTRON_GET_USE_PROXY = '1'
$env:GLOBAL_AGENT_HTTP_PROXY = 'http://127.0.0.1:7892'
$env:ELECTRON_CACHE = Join-Path (Resolve-Path '..') '.ui-checks/electron-cache'
$env:ELECTRON_BUILDER_CACHE = Join-Path (Resolve-Path '..') '.ui-checks/electron-builder-cache'
```

## 隔离验收

在根目录执行 `node tools/browser/integrated_desktop_check.cjs`，使用本机 HTTP 样例验证单一默认入口、数量/配图参数、两类批准展示、题背图、补跑、草稿保护和响应式布局，不读取真实材料或调用云端模型。浏览器可通过 `CHROME_PATH` 指定本机 Chrome。

在 `desktop/` 执行：

```powershell
npm test
npm run test:native
npm run test:frozen
npm run test:connection  # 验证 desktop/dist/win-unpacked 中的真实程序，仅请求本机模拟模型
```

原生验收使用随机空闲端口、隐藏窗口、单独的 `.ui-checks/native-desktop/` 用户目录和演示模式，检查真实后端、静态资源、窗口按钮、渲染器隔离以及退出后的进程清理。`test:frozen` 需要先构建后端。报告和截图保存在对应 `.ui-checks/` 目录。

`test:connection` 在打包后的程序中使用独立用户目录与本机模拟模型，验证配置持久化、成功、凭据错误、地址错误、限流、超时、无效 JSON、页面切换和重启恢复，不请求真实服务商。`node smoke.cjs --packaged` 额外验证随包插件安装到隔离目录与回执展示；真实 Anki 写入另用官方运行时和隔离资料库验收。

`test:connection` 使用 `.ui-checks/native-connection/` 下的独立配置与虚构密钥，覆盖状态颜色、拒绝访问、超时、重试、切换页面、配置保存与服务重启后的状态失效。等待采用定时轮询；截图单独限时，不阻塞功能断言。设置 `ANKISENSE_TEST_EXECUTABLE` 可验收其他目录中的同一程序。测试不会访问真实模型或个人 Anki 资料。

`ANKISENSE_DESKTOP_PORT` 和 `ANKISENSE_DESKTOP_USER_DATA` 仅用于显式覆盖端口/用户目录（主要供隔离测试）；一般用户无需设置。
