# 最小 Anki 同步插件验收

> 归档记录：以下环境、服务状态和结果属于报告日期；历史截图、数据库、JSON 与日志未随源码分发，见[测试记录索引](../README.md)。

本轮实现“网页制卡并批准 → Anki 工具菜单同步 → 在 Anki 复习图文卡片”。PDF 制卡工作台和 Anki 内 AI 答题窗口不属于本轮。验收使用本机安装的官方 Anki 26.09.3、其 Python 3.13.15 和独立测试资料。

## 结果

| 检查 | 结果 | 范围 |
|---|---:|---|
| 客户端与同步下载回归 | 113 项通过 | 本机鉴权、摘要、整批下载、版本变化、重复清单和失败边界 |
| 真实 Anki 集合 | 20 项通过 | 官方 Anki 后端、临时 collection、APKG 与同步写入 |
| 真实 HTTP → Anki 集合 | 11 项通过 | 独立演示服务、真实插件传输、真实集合与图片 |
| 真实 Qt 离屏界面 | 15 项通过 | 菜单、窗口、后台操作、关闭与资料切换 |
| 打包与临时安装 | 10 项通过、5 项跳过 | 文件白名单、模板资源、保留配置与用户文件、目录联接拒绝 |

最终 pytest 命令显示 114 项通过：113 项客户端/传输测试，加 1 个启动官方运行时的包装测试；包装测试内部包含上述 20 项集合测试，不能重复算作 114＋20 个 pytest 用例。

真实集合测试包含：

- 已有 APKG 接管、插件更新后再次 APKG 导入；没有重复笔记或 `conflicting`。
- 通过 `sched.answerCard` 产生真实复习日志，再更新卡片内容；note/card ID、复习日志、调度参数、用户标签和已移动的牌组均保留。
- 首次同步与更新的撤销处理，初始化占位笔记清理，本地编辑/模板/媒体冲突。
- 媒体失败时不写入半张卡片；批次中途失败时记录已经成功的卡片。
- 映射缺失、损坏或不可写时保守处理；清单缺席不会自动删除旧笔记。

真实 HTTP 验收最终记录：`live-130922-4dc47f/anki-profile/acceptance.json`。本项的调度状态为测试种子，真实非空复习日志的保留由前述 20 项集合测试验证。临时服务器已关闭，临时连接已禁用。

UI 烟测使用真实 Qt 控件、QueryOp、CollectionOp、TaskManager 与隔离 Collection，宿主是最小 QMainWindow 测试壳，下载与写入输入使用夹具；不是人工操作完整 Anki 主窗口的录像。回调异常为零。截图位于 `ui-smoke-final/`，已检查中文显示与布局；早期 `ui-smoke/` 调试图不作为验收依据。详见[运行时与离屏验收](运行时与离屏验收.md)。

## 数据与调用范围

测试没有改写个人 Anki 学习集合，也没有调用云端模型。正式 AnkiSense 服务只进行只读连接检查：11 张可用已批准卡片、0 张异常排除卡片。实际插件同步本身也不会触发模型调用。

插件复用同一套客户端、字段、GUID、模板与媒体文件约定。写入通过 Anki 的 Collection API；只读身份查询使用 Anki 自身的 DB 代理，未直接写入或修改 Anki 数据库结构。

## 复现

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_addon_transport.py tests/test_plugin_client.py tests/test_anki_collection_sync.py -q
.\.venv\Scripts\python.exe tools\run_anki_sync_acceptance.py
```

插件源码位于 `addons/ankisense_sync/`，构建命令与用户操作见[Anki 同步插件使用说明](../../Anki同步插件使用说明.md)。
